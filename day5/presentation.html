1الدرس 1 · IsolatesDart

async/await لا يعني «خيطاً جديداً»

  • كل الكود — حتى async — يعمل على الـ Isolate الرئيسي، وهو نفسه الذي يرسم الإطارات.
  • حساب ثقيل (JSON ضخم، صورة، تشفير) = الإطار التالي لا يُرسم ← jank.
  • الـ Isolate عامل مستقل بذاكرة خاصة: لا يشارك المتغيرات، والتواصل بالرسائل فقط.
  • الدالة المرسلة: top-level أو static.
💡 في التطبيق: شعار يدور + عدّاد «أطول توقف بين إطارين» يكشفان التجمّد بالعين.
int countPrimes(int limit) {
  var count = 0;
  for (var n = 2; n <= limit; n++) {
    var isPrime = true;
    for (var d = 2; d * d <= n; d++) {
      if (n % d == 0) {
        isPrime = false;
        break;
      }
    }
    if (isPrime) count++;
  }
  return count;
}

Isolate.run · compute · JSON ضخم

  • Isolate.run: ينشئ Isolate، ينفّذ، يعيد النتيجة، ثم يغلقه.
  • compute: نفس الفكرة من Flutter — وتعمل على الويب (على نفس الخيط).
  • الوقت تقريباً نفسه! لا يصبح الحساب أسرع، بل يبتعد عن الـ UI.
  • المثال الواقعي: 150 ألف منتج من JSON ← compute(parseProducts, body).
// 2) Isolate.run: الطريقة الأسهل والأشهر (Dart 2.19+)
final result = await Isolate.run(() => countPrimes(_limit));

// 3) compute من Flutter: نفس الفكرة + تعمل على الويب
final result = await compute(countPrimes, _limit);

// دالة التحويل: top-level لتعمل مع compute و Isolate.run
List<Product> parseProducts(String body) {
  final list = jsonDecode(body) as List<dynamic>;
  return [for (final m in list)
      Product.fromJson(m as Map<String, dynamic>)];
}

// ✅ التحويل كاملاً في Isolate آخر، والنتيجة تعود جاهزة
final products = await compute(parseProducts, body);

7الدرس 7 · الأمانSecurity

SSL Pinning مع Dio: «لا أثق إلا بشهادة خادمي»

  • HTTPS العادي يثق بأي شهادة موثوقة في الجهاز ← Proxy مثل mitmproxy يقرأ كل شيء.
  • نحسب بصمة SHA-256 للشهادة ونقارنها بقائمتنا.
  • في الشاشة: اكتشف البصمة ← خاطئة 🛑 ← صحيحة ✅.
⚠️ الشهادات تتجدد: ضع بصمة احتياطية وحدّث قبل الانتهاء. على الويب: لا pinning.
dio.httpClientAdapter = IOHttpClientAdapter(
  createHttpClient: () {
    final client = HttpClient();
    // شهادة غير موثوقة من النظام؟ ارفض دائماً (لا تكتب => true أبداً!)
    client.badCertificateCallback = (cert, host, port) => false;
    return client;
  },
  // يُستدعى بعد قبول النظام للشهادة: نتأكد أنها شهادتنا بالضبط
  validateCertificate: (cert, host, port) {
    if (cert == null) return false;
    final fingerprint = certificateFingerprint(cert);
    return allowedFingerprints.contains(fingerprint);
  },
);

  val reasons = mutableListOf<String>()

    "/system/bin/su", "/system/xbin/su", "/sbin/su",
  )
  suPaths.filter { File(it).exists() }
    .forEach { reasons.add(it) }
  return mapOf("compromised" to reasons.isNotEmpty(),
    "reasons" to reasons)
}

تقارير الأعطال: التقط كل خطأ غير معالج

  • FlutterError.onError: أخطاء build / layout / paint.
  • PlatformDispatcher.onError: أخطاء async بلا catch.
  • non-fatal: خطأ التقطناه + سياق (log و setUserIdentifier).
  • محمي مثل FCM: بدون Firebase تظهر الأخطاء في الشاشة.
البديل: Sentry — يعمل أيضاً على الويب و Linux.
static void installHandlers() {
  // 1) أخطاء إطار Flutter (build / layout / paint)
  FlutterError.onError = (details) {
    record(details.exception, details.stack, fatal: true);
    _previousFlutterHandler?.call(details); // نُبقي الطباعة في الـ Console
  };
  // 2) أخطاء async خارج Flutter (Future بدون catch مثلاً)
  PlatformDispatcher.instance.onError = (error, stack) {
    record(error, stack, fatal: true);
    return true; // true = عولج الخطأ
  };
}
